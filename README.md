# Amazon mobile phone cart automation

Playwright + TypeScript with a Page Object Model (POM). The test shops for mobile phones on Amazon.in in desktop Chrome using a fresh guest session. It does not emulate a mobile device or check out.

## What the test checks

1. Search for **mobile phones**.
2. Apply **Redmi** (or Xiaomi) and **Apple** (or iPhone) brand filters and verify both checkboxes remain selected.
3. Open the first eligible result whose title contains Redmi, Xiaomi, or iPhone, skipping results marked as sponsored by the configured selectors.
4. Verify that the add-to-cart form's ASIN matches the selected search result.
5. Click Add to Cart and wait for a visible success confirmation.
6. Open the cart and verify the selected ASIN and product title within the active cart, excluding saved-for-later items.

## Requirements

- Node.js and npm available in your terminal.
- Google Chrome installed. The configuration uses `channel: 'chrome'`.
- Internet access to Amazon.in.

No login command, OTP, or saved cookies are required by the test.

## Setup and run

Run commands from **`amazon-mobile-no-login-pom`**, the inner folder containing `package.json`.

On macOS, open Terminal or the editor's integrated terminal. If you are in the outer `amazon-mobile-cart-pom-main` folder, run:

```sh
cd amazon-mobile-no-login-pom
```

On Windows, open the inner folder in File Explorer, click its address bar, enter `cmd`, and press Enter.

For the first setup, install the dependencies:

```sh
npm install
```

Check TypeScript, then run the test in visible Chrome:

```sh
npm run typecheck
npm run test:headed
```

To run without a visible browser window:

```sh
npm test
```

## Report and screenshots

After a test run, open the HTML report:

```sh
npm run report
```

The command starts a local report server and opens the report in your browser. Use the URL printed in the terminal (normally `http://localhost:9323`). Press **Ctrl+C** in that terminal to stop the server.

- `playwright-report/`: HTML report with named test steps and screenshot attachments. Expand the test to view `filtered-brands` and `cart-verified`; each screenshot is attached only after its corresponding checks pass.
- `test-results/`: test artifacts, including a failure screenshot and retained trace when a browser test fails. Videos are disabled.

## Project files

- `pages/HomePage.ts`: search for mobile phones.
- `pages/SearchResultsPage.ts`: apply and verify filters, then select a product.
- `pages/ProductPage.ts`: verify the ASIN, add the phone, and open the cart.
- `pages/CartPage.ts`: verify the item in the active cart.
- `tests/mobile-cart.spec.ts`: complete test flow, named steps, and screenshot attachments.
- `playwright.config.ts`: desktop Chrome, timeouts, and reporting settings.
- `tsconfig.json`: TypeScript checks with `Node16` module settings and no emitted JavaScript.

## Practical limits

- Amazon may require sign-in or present a CAPTCHA. The test does not automate either; the run may fail when they block the flow. Its browser session does not reuse your ordinary Chrome login.
- Brand filters, page layouts, and sponsored markers can change. The test fails if its required filters or checks cannot be satisfied.
- The selected phone depends on the current search results. The test does not guarantee a particular model, price, or brand on every run.
- Products requiring variant selection, unavailable offers, or extra dialogs can cause a failure. The test does not try another product after opening the selected result.
- Inspect the failed step, screenshot, and trace in the report to diagnose a failure. Reports and test artifacts are regenerated by subsequent runs.
